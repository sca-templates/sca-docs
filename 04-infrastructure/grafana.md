# Grafana

> Central visualization and alerting for the stack, backed by the Prometheus TSDB. UI on `http://127.0.0.1:3000` (loopback only). Dashboards, alert rules and data sources are provisioned from versioned files — never created by hand in the UI.

## Role in the stack

A Compose stack inside `aws/grafana/`, lifted by the root orchestrator (`make grafana-up` / `make all`, ordered after `prometheus-up`):

- **grafana** — `grafana/grafana:11.1.0`, host network, UI on `127.0.0.1:3000` (`GRAFANA_PORT`).
- Single Prometheus datasource (`uid: prometheus`) at `http://127.0.0.1:9090`.
- Provider `sca-local` loads 5 versioned dashboards (`dashboards/*.json`): `infra-local`, `ms-auth-local`, `ms-notifications-local`, `ms-logging-local`, `ms-ai-local`.
- Alerting provisioned by file: contact point `sca-local` (loopback webhook, no external integration), root notification policy, and two rule groups — `infra` active, `microservices` `isPaused` until the services exist.

## Networking

- **Grafana runs on the host network** (`network_mode: host`) and binds its UI to loopback only (`GF_SERVER_HTTP_ADDR=127.0.0.1`, `GF_SERVER_HTTP_PORT=3000`, `GF_SERVER_ROOT_URL=http://127.0.0.1:3000`). Host-network mode is required because the host firewall (UFW, default deny) drops Docker-bridge → host-network traffic. The Prometheus datasource URL is therefore `http://127.0.0.1:9090` — never a `kafka-network` container name.
- There is no `depends_on` across compose files; the root orchestrator guarantees the order (`prometheus-up` before `grafana-up`).
- The `grafana_data` named volume keeps `/var/lib/grafana`; `provisioning/` and `dashboards/` are mounted read-only.

## Provisioning (as code)

- **Data source**: `provisioning/datasources/datasources.yml` — Prometheus (`uid: prometheus`, `isDefault`, `editable: false`). Loki/Tempo blocks stay commented until those services exist.
- **Dashboards**: provider `sca-local` refreshes every 30s (`allowUiUpdates: false`); `infra-local` uses live verified series (`vault_*`, `pg_stat_*`, `redis_*`, `prometheus_tsdb_*`), the microservice dashboards follow the KB metric contracts (`node/nest-template/docs/kb/ms-*.md`) and render "No data" without panel errors until the services run.
- **Alerting**: `provisioning/alerting/` — contact point, notification policy and rules; `infra` rules are active (`up == 0` for 2m, severity `warning`), microservice rules are `isPaused` with YAML comments describing how to enable them.

## Secrets flow

1. `grafana/scripts/vault-secrets.sh` registers the `grafana` AppRole and writes a generated `GF_SECURITY_ADMIN_PASSWORD` into Vault `secret/grafana/dev` (idempotent; `FORCE=1` regenerates).
2. `grafana/scripts/gen-env.sh` reads the secret and writes the gitignored `.env` (`chmod 600`).
3. Compose interpolates `.env` (`GF_SECURITY_ADMIN_USER`, `GF_SECURITY_ADMIN_PASSWORD`, `GRAFANA_PORT`) with `${VAR:-default}` defaults so CI passes without secrets.

## Access

| Endpoint | Local (development) | Notes | Production |
|---|---|---|---|
| UI + API | `http://127.0.0.1:3000` | loopback only; user `admin` | Same image; provisioned via config management |
| Health | `http://127.0.0.1:3000/api/health` | `"database": "ok"` | Same |
| Datasources | `http://127.0.0.1:3000/api/datasources` | Prometheus, basic auth | Same |
| Dashboards | `http://127.0.0.1:3000/api/search` | 5 dashboards under `sca-local` | Same |

Credentials source: `.env` generated by `grafana/scripts/gen-env.sh` from Vault `secret/grafana/dev`.

## Consul registration

[[consul]] registers `grafana:3000` with a TCP check on `127.0.0.1:3000`.

## Known gaps (informative, not panel errors)

- Consul exports no telemetry (`consul_*` absent — only `up`); Kafka Connect exposes no JMX without `JMXPORT=8778` (`debezium_*` absent). Both are documented in [prometheus](https://github.com/sca-templates/prometheus).
- Microservice dashboards are populated-empty until the services run.
