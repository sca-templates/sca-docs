# Prometheus

> Central TSDB (30-day retention) scraping Vault, Consul, Postgres, Redis and Kafka Connect (Debezium CDC), with bundled exporters. UI on `http://127.0.0.1:9090` (loopback only).

## Role in the stack

A Compose stack inside `aws/prometheus/`, lifted by the root orchestrator (`make prometheus-up` / `make all`):

- **prometheus** — `prom/prometheus:v2.53.0`, 30-day retention, `--web.enable-lifecycle`.
- **postgres-exporter** — `:9187`, connects to `postgres-app-db:5432`.
- **redis-exporter** — `:9121`, reaches Redis via `host.docker.internal:6379`.
- **kafka-connect-exporter** — `:9309`, JMX metrics of Kafka Connect; image `bitnamilegacy/jmx-exporter:0.20.0` (the `bitnami/` one no longer exists on Docker Hub). The broker job (`:9308`) stays commented.

## Networking

- **Prometheus runs on the host network** (`network_mode: host`) and binds its UI/API to loopback only (`--web.listen-address=127.0.0.1:9090`). This is required because the host firewall (UFW, default deny) drops Docker-bridge → host-network traffic — Consul (on `network_mode: host`) would be unreachable otherwise. Every scrape target is therefore a published `127.0.0.1:<port>`.
- The **exporters** join the external `kafka-network`: postgres-exporter resolves `postgres-app-db:5432`, kafka-connect-exporter resolves `kafka-connect:8778` (JMX).
- **Redis** is not on `kafka-network`; redis-exporter reaches it via `host.docker.internal` (`extra_hosts: host-gateway`).
- The Vault token is mounted read-only from `vault/data/secrets/root-token.txt` → `/etc/prometheus/vault-token`; after a Vault re-init, re-run `make up`.

## Scrape targets

All targets are `127.0.0.1:<port>` (published loopback) except `kong` (host-network name, tolerated down until the stack exists):

| Job | Target | Notes |
|---|---|---|
| prometheus | `127.0.0.1:9090` | self-scrape |
| vault | `127.0.0.1:8201` | `https`, bearer token; strict — the `vault/` HCL sets `telemetry.prometheus_retention_time` |
| consul | `127.0.0.1:8500` | `/v1/agent/metrics?format=prometheus` |
| kong | `kong:8001` | tolerated down (no stack yet) |
| postgres-exporter | `127.0.0.1:9187` | `pg_*` |
| redis-exporter | `127.0.0.1:9121` | `redis_*` |
| kafka-connect | `127.0.0.1:9309` | JMX; needs `JMXPORT=8778` on `kafka-connect` |

Commented until a real target exists: broker kafka-exporter (`127.0.0.1:9308`) and microservices (`127.0.0.1:9101`–`9104`).

| Endpoint | Address | Notes |
|---|---|---|

| Health | `http://127.0.0.1:9090/-/healthy` | container healthcheck |

| redis-exporter | `http://127.0.0.1:9121` | |
| kafka-connect-exporter | `http://127.0.0.1:9309` | JMX over HTTP |

Credentials source: `.env` generated by `prometheus/scripts/gen-env.sh` from Vault `secret/postgres-app/dev` + `secret/redis/dev` (read via the `prometheus` AppRole).

## Consul registration

[[consul]] registers prometheus and the exporters with TCP checks on `127.0.0.1:<port>`: `prometheus:9090`, `postgres-exporter:9187`, `redis-exporter:9121`, `kafka-connect-exporter:9309`.
